## 0. 结论先行

**从 2026-11-12 起，每一次提问都要「文档 + 对话」双通道输出：既落盘，也在对话里把答案完整再讲一遍。缺任何一边都算没完成。**

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | 提炼知识点 | 结论 + 可复用要点 + 证据（文件:行 / 实测命令 / `cv2.__doc__`） |
| 2 | 按主题补进 `docs/` | 修订已有手册章节，或新建专题手册 |

| 5 | **在对话里把答案完整再解释一遍** | 不打开文档也能读懂的独立答案（判定线见 §7） |

## 1. 规则细则

### 1.1 什么算「知识点」

不是把聊天记录复制粘贴。必须提炼成下面 4 类之一：

| 类型 | 说明 | 例子 |
|---|---|---|
| 概念 / 原理 | 能回答「为什么」 | Python 绑定由带 `CV_EXPORTS_W` 的 C++ 声明编译期生成 |
| 可复用结论 | 能直接指导决策 | 跳过 4.x，主学 5.x |
| 操作 / SOP | 能照着做 | 四层阅读法；docx 定点替换顺序 |
| 反常识 / 坑 | 会让人踩雷 | 长 URL 必须先于短 URL；插值数值差异污染测量基线 |

**判定标准**：写完能出一道自测题，且能在文档里指出答案在哪一节。做不到，就说明那只是「回答」，不是「知识点」。

### 1.2 什么时候算这一轮完成

- [ ] 聊天里给了**自包含的完整答案**（不是「已写进文档，见某节」；判定见 §7）
- [ ] `docs/` 里有用户能打开读到的对应文字（**写进记忆文件不算**）
- [ ] §4 台账多了一行
- [ ] 当天工作区日志追加了一条
- [ ] §5 的结构校验通过
- [ ] §7 的双通道判定线 1–4 全部满足（先答、后报改动）

### 1.3 用户没问、但过程中发现的问题

一并提炼，在同一条台账里标「顺带」，不单独开一轮，也不另建文件。

## 6. 常见误解

| 误解 | 正解 |
|---|---|
| 「写进记忆文件就算沉淀了」 | 不算。必须在 `docs/` 里有用户能打开读到的文字 |
| 「每次提问都新建一份手册」 | 不是。优先补进已有对应手册，跨主题 / 体量大才新建 |
| 「把聊天内容整理成 FAQ 就行」 | 不行。要提炼成概念 / 结论 / SOP / 坑，并挂到 S、T、W 编号与答案索引 |
| 「改文档插在最前面更醒目」 | 会挤偏 `docs/00:120` 等行号引用，追加放末尾 |
| 「旧字样还搜得到就是没改干净」 | 带否定或历史标注（如「4.x 旧口径已过时」）是有意保留的对照说明 |
| 「答案写进文档了，对话里给个链接就行」 | 不行。§7 要求对话答案自包含，文档是补充不是替代 |
| 「对话讲太细会和文档重复」 | 允许重复：文档重「以后查得到」，对话重「现在就懂了」，读者状态不同 |

## 7. 双通道输出：文档与对话各写一份完整答案（Q08 / 2026-11-12）

> 用户补充要求原话：「**把知识点补充进去也要在对话中把答案再解释一遍**」。本节是与 §1「必须落盘」**并列**的第 2 条硬约束，不是二选一。

### 7.1 为什么单有文档不够

文档解决「**以后查得到**」，对话解决「**现在就懂了**」。两者读者状态不同：文档是**索引型**（可跳读、可只查某节、可引用别的章节），对话是**线性型**（用户不会为了看懂一句结论去打开另一个文件）。因此把答案压缩成「已补充到 `docs/10` §9，详见文档」是典型违规输出。

### 7.2 判定线（4 条，逐条自查）

| # | 要求 | 反例 |
|---|---|---|
| 1 | **结论先行**，第一句就回答问题 | 先讲「我查了哪些文件、改了哪些手册」 |
| 2 | 对话答案**自包含**：不看文档也能懂 | 「原理见 `10` §9.3」「上面那张图已经画了」 |
| 3 | 保留**关键证据与推导**：源码行号、实测数值、代码片段、报错原文 | 只给一句结论 + 一串文件链接 |
| 4 | 保留**可复用件**：表格 / 可复制代码 / Java 类比 / 易错点 | 把表格和代码全塞进文档，对话只剩摘要 |

> **与 §1.1「提炼」的区别**：§1.1 管「文档里写什么」（必须能出自测题、能指到答案节）；本节管「对话里讲什么」（必须完整、独立、当场能读懂）。同一知识点两边都要有，组织方式可以不同。

### 7.3 允许与不允许

| 允许 | 不允许 |
|---|---|
| 对话给完整答案，末尾再附「已沉淀到 `docs/10` §9」 | 对话只说「已沉淀到 `docs/10` §9，去看文档」 |
| 文档写更细的推导与自测题，对话给核心推导 | 对话给结论，把「为什么」全推给文档 |
| 用图辅助解释，同时用文字把图的内容说清 | 用一张图代替文字解释 |
| 长内容在对话里给结构化摘要 + 关键数字 | 用「细节较多，见文件」打发 |

### 7.4 顺序约定

**先答，后报改动。** 对话结构固定为：结论 → 推导 / 证据 → 代码或表格 → 易错点 →（最后）本轮沉淀了哪些文件。改动汇报永远放最后，且不能挤掉前面的解释。Q07 已按此顺序执行，Q08 起作为硬性顺序。
