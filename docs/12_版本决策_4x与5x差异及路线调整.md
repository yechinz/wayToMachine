## 1. 权威依据（不是博客推测）

官方迁移指南在「calib3d 拆分」「features2d 改名」「imgproc 几何函数搬家」三节里，反复写同一句话：

> **Python: no changes required.** All functions remain accessible as `cv2.<funcname>()`.

指南的 Python bindings 小节进一步明确：

> **Module restructuring is fully transparent**: all functions remain accessible as `cv2.<funcname>()` regardless of which C++ module they now live in. **No import changes are needed.**

也就是说，C++ 头文件怎么拆、Java 包名怎么改，对 Python 是**刻意做成透明**的。这是 OpenCV 团队的设计目标，不是巧合。

另外：4.x 并未停更（4.14.0 于 2026-07 发布），两条线并行维护、改进互相 backport。**5.x 不是"取代 4.x 的新语言"，是同一套 API 的新实现**。

## 2. 差异分层：哪层变了、要不要管

| 层 | 变了吗 | 对你的影响 | 要不要管 |
|---|---|---|---|
| **算法与概念层**（阈值、滤波、形态学、Canny、轮廓、几何变换、标定、特征匹配） | **完全没变** | 数学原理和调参经验 20 年通用；`04`/`05`/`06` 号手册知识 100% 有效 | ❌ 不管 |
| **Python API 层**（`cv2.xxx` 函数名、参数顺序、import） | **几乎没变** | 4.x 教程代码可直接粘贴运行 | ❌ 不管 |
| **数值 / 行为层**（resize 舍入、warp 插值、putText 字体、1D 数组、VideoCapture.get） | **有微变** | ⚠️ **对像素级基线和尺寸测量精度有影响**（见 §4） | ✅ 要管 |
| **模块 / 打包层**（`ml`、Haar、HOG、Caffe/Darknet、contrib 扩展模块仓库） | **变化明显** | 用到才管；你的 W1–W8 主线未使用 | ⚠️ 用时管 |
| **底层构建层**（C++17、C API 删除、模块拆分、Java import） | **大变** | Python 学习者完全不涉及 | ❌ 不管 |

> **Java 类比**：这像 Spring Boot 2 → 3 换 `javax.*` 到 `jakarta.*`。业务逻辑一行不用重写，但 import 和少数配置你得认得。**你学的是业务逻辑，不是迁移史**——所以直接学 5.x 是对的，将来遇到 4.x 代码能认出差别就够。

## 3. 官方迁移清单：真正影响 Python 的 10 项（含本机实测）

| # | 变化 | 官方说明 | 本机 `5.0.0.93` 实测 |
|---|---|---|---|
| 1 | `cv2.ml.*` 移到 contrib | 主包不再含 ML 模块，建议改用 scikit-learn | **`hasattr(cv2,'ml') == False`** |
| 2 | `CascadeClassifier`（Haar）、`HOGDescriptor` 移到 contrib `xobjdetect` | 新项目建议用 `FaceDetectorYN` | **均为 False** |
| 3 | `readNetFromCaffe` / `readNetFromDarknet` 删除 | 模型统一转 ONNX | **均为 False** |
| 4 | 1D 数组语义 | `np.array` 传入 `InputArray` 现在映射为真 1D `Mat`（4.x 是 N×1 列向量）；别用 `.rows` 当元素个数 | `np.array([1..5])` 传入 `cv2.mean` 正常返回 3.0 |
| 5 | `INTER_NEAREST` 舍入 | 改为对齐 Pillow，`INTER_NEAREST == INTER_NEAREST_EXACT` | 常量在，输出与 4.x 边界像素可能不同 |
| 6 | `warpAffine` / `warpPerspective` / `remap` | 双线性、双三次不再用查表近似，**数值输出与 4.x 略有差异**（新值更接近精确解），速度更快 | `hint` 参数存在（见下方纠错） |
| 7 | `putText` 新 TrueType 引擎 | `FONT_HERSHEY_*` 仍在、无需改代码，但改用内嵌 Rubik 字体，**外观明显不同**；新增 `cv2.FontFace` | `FONT_HERSHEY_SIMPLEX` 与 `FontFace` **都在** |
| 8 | `VideoCapture.get` | 后端不支持的属性返回 `-1` 而非 `0` | 未实测（本项目暂无相机链路） |
| 9 | DNN 新引擎 | `ENGINE_AUTO` 默认先试新引擎再回退 classic；新引擎 **CPU-only** | 实测常量：`ENGINE_AUTO / ENGINE_CLASSIC / ENGINE_NEW / ENGINE_ORT` |
| 10 | **纯增益** | 关键字参数、PEP 484 类型注解（Python 类型提示）、NumPy 2.x、`FontFace`（新字体类）、ALIKED/DISK/LightGlue（新特征点算法）、USAC 默认（更稳健的 RANSAC） | `cv2.warpAffine(src=…, M=…, dsize=…)` **可用**；`SIFT_create / aruco / FaceDetectorYN` **主包就有** |

### 对 `11` 号手册的一处纠错（已同步修正）

`11` 号手册上一版推测「5.x 源码里 `warpAffine` 的 `hint` 参数可能不在 5.0.0 中」。**实测证伪**：

```
cv2.warpAffine.__doc__ 首行：
warpAffine(src, M, dsize[, dst[, flags[, borderMode[, borderValue[, hint]]]]]) -> dst
```

`hint` 在 5.0.0 里确实存在。真正的版本差是：本地源码是 **5.1-dev**（`docs_sphinx/conf.py:27` → `release = "5.1"`），DNN 引擎常量开发版叫 `ENGINE_OPENCV`，5.0.0 叫 `ENGINE_NEW`。`11` 号手册 §3 已更正。

## 6. 三层学习策略（推荐执行）

| 层次 | 做法 | 投入 |
|---|---|---|
| **主线（95%）** | 5.0 官方文档 + 本地 5.1-dev 源码，按 `11` 号手册的**四层阅读法**走 | 维持原 48 周节奏，不变 |
| **遇到 4.x 资料时** | 当伪代码读：算法思路照抄，函数签名用 `cv2.__doc__` 校验，版本号相关常量不照抄 | 每次 1 分钟 |
| **补 4.x 的时机** | 仅三种情况：① 接手旧项目 ② 网上代码报错且定位为版本差异 ③ 面试被问版本差异。届时读一遍官方迁移指南即可 | 一次性 1–2 小时，**不单独开学习轮次** |

**明确不要做的事：**
- 不要为了"打基础"先装一个 4.x 环境再学一遍——`opencv-python` 与 `opencv-contrib-python` 两个 wheel **互斥**（一个环境只能装一个；这里说的不是 4.x 与 5.x 之间互斥），来回切换只会浪费时间。
- 不要把 `11` 号手册里 5.1-dev 源码的参数直接抄进代码，一律以本机 `__doc__` 为准。
- 不要因为"网上教程都是 4.x"就怀疑自己学错了版本：算法层完全一致，差异集中在 §3 那 10 项。
